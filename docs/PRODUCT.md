# ModelProbe 产品场景与验收规则

本文基于现有工具整理，采用 AI 辅助编写。目标开发者的需求和使用流程仍待真实访谈验证；当前没有真实模型在线质量结果或商业使用数据。

## 用户与使用场景

目标用户假设为接入模型 API 的开发者或参与 AI 功能验收的产品人员。当提示词、模型配置或接口适配发生变化时，需要重新确认接口是否可用、输出是否符合程序约定，并定位失败原因。

产品目标是把重复的人工检查转换为一组可复现用例和报告。范围集中在接口与输出格式，不提供回答语义质量排名。

## 任务流程

配置用例 → 选择本机模拟或显式在线模式 → 设置并发与重试上限 → 执行请求 → 分别检查 API 与输出约定 → 查看逐题原因及汇总 → 修改后重跑。

用例包含唯一编号、提示词和检查规则。支持必需 JSON 字段与基础类型、关键词两类检查。报告输出 JSON 与 HTML，没有单独的交互式管理后台。

## 需求优先级与取舍

| 优先级 | 内容 | 理由与状态 |
| --- | --- | --- |
| P0 | 区分请求成功与格式检查通过 | 已实现，避免接口成功掩盖输出不符合约定 |
| P0 | 错误原因、超时和有限重试 | 已实现，帮助判断是临时错误、鉴权问题还是内容问题 |
| P0 | 本机模拟服务 | 已实现，无密钥即可复现限流和错误场景 |
| P1 | 有界并发与 JSON HTML 报告 | 已实现，减少逐题操作并便于检查结果 |
| 后续 | 真实模型对照、语义评分、流式请求 | 尚未验证或尚未实现，需分别建立明确范围 |

## 验收标准

| 类别 | 输入或故障 | 预期 |
| --- | --- | --- |
| JSON 约定 | 要求 name 为字符串、skills 为数组 | 分别检查 JSON 可解析、字段存在与基本类型 |
| 内容检查 | 用例要求出现 Python | 依据关键词规则判断，不自动推断语义正确性 |
| 临时错误 | 模拟 429 或 503 后恢复 | 在设置上限内重试，报告实际请求次数 |
| 鉴权失败 | 模拟 401 | 记录错误，不作无意义重复请求 |
| 输出异常 | 无效 JSON、缺字段、协议损坏或空响应 | 保留失败分类，不将其记作正常通过 |
| 报告展示 | 模型输出含 HTML 字符 | 报告转义展示，避免作为页面代码执行 |

实现见 `model_probe/client.py`、`evaluation.py`、`mock_server.py` 和 `report.py`；用例见 `datasets/cases.json`。

## 指标口径与已有验证

- API 成功率：成功取得有效模型消息的用例数 / 全部用例数。
- 约定通过率：请求成功且通过指定检查的用例数 / 全部用例数。仅验证字段、基础类型或关键词。
- P50 P95：成功请求完整耗时的分位数，包含重试等待；不代表首 Token 延迟，也不是生产压测。
- 用量：只记录接口实际返回的 Token 数据，缺失时标记缺失。

20 项自动化测试通过。12 个本机演示用例会故意包含失败，演示报告用于验证错误处理；其通过率、耗时和 Token 数据不能作为真实模型表现。

## 待开展的用户与在线验证

先观察少量开发者能否根据报告区分“接口出错”和“输出格式不符”，记录定位错误所需步骤及误解。该任务尚未开展。

真实接口验证应固定题集、提示词、模型版本和请求配置，保存不含密钥的运行记录，确认费用范围后再运行。若需要评价回答正确性，应另外加入人工标注与语义评分标准，不能用格式通过率代替。
